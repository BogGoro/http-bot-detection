# Detecting Bots in Real HTTP Sessions

Поведенческая детекция ботов на реальных HTTP-логах с аудитом разметки, ablation-исследованием и продуктовой схемой триажа.

## TL;DR

- Данные: 67 352 реальные HTTP-сессии (Zenodo 3477932, Университет Аристотеля, Греция).
- Главный результат: поведенческая модель V5 = 0.9704 ROC-AUC на 17 фичах без единого признака о типах контента.
- Аудит разметки: прямой утечки нет (V1 = V2 = 0.9957). Гипотеза о доминирующем признаке опровергнута через leave-one-feature-out.
- Продуктовая схема: триаж auto-ban / review / skip с precision-порогами. V5 - приоритизатор для ансамбля, а не автобаннер.
- Предел поведенческой детекции: 0.9% «умных» ботов неотличимы от людей по поведению.

## 1. Задача

Антибот защищает маркетплейс от автоматизированного трафика. Модель должна отличать сессии ботов от сессий людей по поведенческим признакам.

Ключевые требования:

- FP (блокировка легитимного покупателя) - дорого.
- FN (пропуск бота) - дёшево, системы защиты сработают позже.
- Модель должна быть устойчива к мимикрии: умные боты грузят статику и имитируют тайминги.

## 2. Данные

Источник: Zenodo 3477932 - логи поисковой системы библиотеки Университета Аристотеля (Греция), март 2018.

- Всего сессий: 67 352
- Признаки: simple_features.csv (32) + semantic_features.csv (6)
- Дисбаланс классов: 80% человек / 20% бот
- Разметка: полуавтоматическая (Udger + User-agents + поведенческие эвристики)

В статье (Springer, 10.1007/s10489-020-01754-9) описан сбалансированный набор 6 190 / 7 200 после исключения «undecided» сессий. На Zenodo лежит полная версия - все сессии с любыми метками. Это отличие объясняет все результаты ниже.

## 3. Аудит разметки

Правила разметки из статьи - жёсткие эвристики. Воспроизведены на полной версии:

- IMAGES == 0: BOT=8 073, HUMAN=11 040, purity(bot)=0.42
- SF_REFERRER == 0: BOT=5 170, HUMAN=2 802, purity(bot)=0.65
- HTTP_RESPONSE_4XX == 1.0: BOT=196, HUMAN=243, purity(bot)=0.45
- HEAD_METHOD == 1.0: BOT=91, HUMAN=27, purity(bot)=0.77

В полной версии правила недетерминированы - метка ROBOT не восстанавливается по правилам однозначно. Прямой утечки нет. Подтверждено экспериментом: V1 (все фичи) = V2 (без правил) = 0.9957.

## 4. Гипотеза, которая не подтвердилась

Permutation importance на V2 показал UNASSIGNED = 0.1523, в 26 раз больше следующего признака. Гипотеза «90% сигнала в одном признаке» опровергнута:

- V3 (без группы UNASSIGNED, HTML_TO_CSS/JS, SF_FILETYPE) = V4 (без UNASSIGNED отдельно) = 0.9897.
- UNASSIGNED был «представителем» коррелированной группы. Permutation importance сваливает всю важность на одного.
- Leave-one-feature-out показал реальный топ: DATA (Δ −0.0063), остальные - на уровне шума.

Урок: permutation importance на коррелированных фичах обманчив. Правильный метод - групповой ablation (см. V5).

## 5. Модели

- V1: 40 фич, все (включая правила), ROC-AUC = 0.9957
- V2: 29 фич, без прямых правил, ROC-AUC = 0.9957, CV = 0.9951 ± 0.0002
- V3: 24 фичи, без поведенческих прокси, ROC-AUC = 0.9897
- V4: 24 фичи, без UNASSIGNED, ROC-AUC = 0.9897, CV = 0.9888 ± 0.0002
- V5: 17 фич, только поведение, ROC-AUC = 0.9704, CV = 0.9692 ± 0.0014

V1 = V2 - прямой утечки нет. V3 = V4 - гипотеза о доминирующем признаке опровергнута. V5 - 0.9704 на чистом поведении, главный результат.

## 6. Главный результат: V5

V5 использует только время, интенсивность и структуру обхода, без типов контента.

Топ-признаки:

- cv_time: 0.183 - регулярность интервалов (std / mean), у бота стремится к 0
- MAX_BARRAGE: 0.137 - пиковая очередь запросов подряд
- NUMBER_OF_REQUESTS: 0.094 - объём сессии
- WIDTH: 0.083 - широта обхода сайта
- DEPTH: 0.077 - глубина обхода
- TOTAL_DURATION: 0.064 - время сессии
- request_rate: 0.063 - запросов в секунду

Умный бот может мимикрировать под человека по контенту и обходить правило IMAGES == 0. Но подделать ровный таймер (cv_time) и аномальную структуру обхода (WIDTH, DEPTH) сложнее. V5 ловит именно эту устойчивую часть поведения.

## 7. Продуктовая схема: триаж

V5 - не автобаннер, а приоритизатор для ансамбля. Пороги подобраны по precision.

- Skip, p < 0.20: 68% трафика, 30 ботов, 11 459 человек, 0.3% ботов, действие - пропуск
- Review, 0.20 ≤ p < 0.985: 29% трафика, 2 883 бота, 2 003 человека, purity 0.59, действие - ансамбль + ревью
- Auto-ban, p ≥ 0.985: 3% трафика, 460 ботов, 3 человека, precision 0.994, действие - автобан + вторичная проверка

Ключевые цифры:

- 85.5% ботов попадают в review-зону - главная работа V5.
- Purity в review-зоне 0.59 против 0.20 в исходном тесте - lift в 3 раза.
- Auto-ban: 460 ботов, 3 FP (0.65%), безопасно для первого слоя.
- Пропущено: 30 ботов (0.9%) - предел поведенческой детекции.

Логика порогов:

- Auto-ban (0.985): precision ≥ 0.99, безопасно для автоматического бана. FP = забаненный покупатель - дорого.
- Review (0.20): precision ≈ 0.59, зона для ансамбля и ручной проверки. FP = лишняя работа саппорта - дёшево.
- Skip (0.20): 0.26% ботов, безопасно пропускать.

## 8. Precision/Recall tradeoff

- threshold 0.30: precision 0.663, recall 0.982 - ловим почти всех, но 34% FP, недопустимо
- threshold 0.50: precision 0.702, recall 0.960 - много FP
- threshold 0.70: precision 0.716, recall 0.928 - разумный баланс для review
- threshold 0.82: precision 0.784, recall 0.779
- threshold 0.90: precision 0.888, recall 0.550
- threshold 0.985: precision 0.994, recall 0.136 - безопасный автобан

Обрыв precision при recall > 0.95 - фундаментальное свойство поведенческой детекции. Последние 5% ботов - умные, их вероятности пересекаются с человеческими.

## 9. Предел поведенческой детекции

30 ботов (0.9%) в skip-зоне - умные боты с человеческими таймингами и нормальной структурой обхода. V5 принципиально не может их отделить от людей.

Их ловят другие сигналы: IP-репутация (known attack sources, ASN, гео), TLS-fingerprint (JA3/JA4), HTTP-заголовки (порядок, Accept-*, Sec-Fetch-*), User-Agent (V5 его намеренно игнорирует).

Вывод: поведение - не панацея. В продакшене нужен ансамбль: V5 (поведение) + контент + IP + TLS + HTTP + правила.

## 10. Как запустить

Установить зависимости: pandas, numpy, matplotlib, scikit-learn, jupyter.

Скачать данные Zenodo 3477932 и распаковать в data/: simple_features.csv и semantic_features.csv.

Открыть bot_detection.ipynb. Ноутбук полностью воспроизводим: random_state=42 везде.

## 11. Что показывает ноутбук

1. Аудит разметки - правила из статьи против реальных данных, purity по каждому правилу.
2. Ablation V1-V5 - пять моделей, каждая проверяет свою гипотезу.
3. Permutation importance - и демонстрация её ограничения при коррелированных фичах.
4. Leave-one-feature-out - надёжная оценка вклада каждой фичи.
5. Корреляция с UNASSIGNED - разделение независимых и коррелированных признаков.
6. Cross-validation - стабильность оценок (std ≈ 0.001).
7. Precision/Recall - продуктовые пороги для антибота.
8. Триаж по зонам - auto-ban, review, skip с реальными цифрами.
9. Визуализации - ROC, PR-кривая, распределение вероятностей, feature importance.

## 12. Ключевые выводы

1. Прямой утечки разметки нет. V1 = V2 = 0.9957, правило IMAGES == 0 в полной версии ловит и людей.
2. Permutation importance обманчив при корреляциях. Гипотеза о доминирующем UNASSIGNED опровергнута через leave-one-feature-out.
3. Поведение работает само по себе. V5 = 0.9704 без типов контента - модель ловит cv_time, MAX_BARRAGE, WIDTH, DEPTH.
4. V5 - не автобаннер, а приоритизатор. Триаж даёт lift в 3 раза по purity в review-зоне.
5. Предел поведенческой детекции честно назван. 0.9% умных ботов - для них нужен ансамбль с IP/TLS/HTTP.
6. Порог - продуктовое решение. Auto-ban при precision ≥ 0.99, review при precision ≈ 0.59, skip для чистых людей.
